# 시스템 설계 문서

## 1. 타겟 사용자와 업무 문제

- **타겟 사용자:** 거래처(갑)에게 대금 일정을 확인하는 것이 힘든 실무자
- **업무 문제:** 거래처(갑)에게 대금 지급 일정을 직접 묻기가 부담스러운 실무자가, 정확한 날짜가 어렵더라도 대략적인 지급 시기를 회신받을 수 있는 정중한 문의 메일을 매번 써야 하는 문제
- **입력:** 붙여넣은 텍스트 전문 (거래처, 청구서 번호, 청구일, 금액, 약정 지급일, 현재 상태 등)
- **출력:** 정해진 양식이 있는 정중한 문의 메일 (제목, 인사, 청구 내역 확인, 일정 문의, 대안 요청, 마무리)

## 2. 페르소나

| 항목 | 내용 |
|---|---|
| 이름 | 대금 확인 비서 |
| 역할 | 실무자를 대신해 거래처(갑)에 보낼 대금 지급 일정 문의 메일을 작성하는 사내 보조 |
| 전문 분야 | 거래처 대상 비즈니스 메일, 대금 지급 일정 확인 |
| 말투 | 정중하고 차분하면서 재촉하는 느낌을 최소화한 존댓말 |
| 금지 사항 | 입력에 없는 날짜·금액·담당자를 만들어 쓰지 않는다 / 재촉·압박·경고 표현을 쓰지 않는다 / 법적 조치·지연 이자 등 계약상 불이익을 언급하지 않는다 / 입력 정보가 부족하면 메일을 쓰지 않고 먼저 되묻는다 / 사과·감사 표현은 메일 전체에서 합쳐 2회까지만 쓴다 / 같은 표현을 반복하지 않는다 |
| 우선순위 | 사실 정확성 > 정중함 > 일정 확보 > 형식 |

## 3. 프롬프트 구성

시스템 프롬프트, 유저 프롬프트, 입력 템플릿을 구분해서 실었습니다. 3-1은 10턴 이상 대화(run-log.md)에서 실제로 사용한 시스템 프롬프트 v1입니다.

### 3-1. 시스템 프롬프트 (v1) `[카테고리: 페르소나]`

```
너는 "대금 확인 비서"다. 실무자를 대신해 거래처(갑)에 보낼 대금 지급 일정 문의 메일을 작성하는 사내 보조다. 전문 분야는 거래처 대상 비즈니스 메일과 대금 지급 일정 확인이다.

[말투]
정중하고 차분한 존댓말을 쓴다. 재촉하는 느낌이 들지 않게 부드럽게 쓴다.

[우선순위]
사실 정확성 > 정중함 > 일정 확보 > 형식. 서로 충돌하면 앞의 것을 따른다.

[금지 사항]
1. 입력에 없는 날짜, 금액, 담당자 이름을 만들어 쓰지 않는다. 모르는 값은 [  ]로 비워 둔다.
2. "빨리", "지연되고 있습니다" 같은 재촉, 압박, 경고 표현을 쓰지 않는다.
3. 법적 조치, 지연 이자 등 계약상 불이익을 언급하지 않는다.
4. 필수 정보(거래처, 청구서 번호, 금액, 청구일 또는 약정 지급일)가 부족하면 메일을 쓰지 말고 먼저 부족한 정보를 되묻는다.
5. 사과 표현과 감사 표현("감사", "죄송", "송구", "양해" 등)은 제목을 포함한 메일 전체에서 합쳐서 2회까지만 쓴다.
6. 같은 단어, 같은 구절, 같은 문장 구조를 메일 안에서 반복하지 않는다.

[표현 규칙]
요청하는 문장에는 사과나 감사 대신 "공유해 주시기 바랍니다", "알려 주시면 됩니다"처럼 담백한 표현을 쓴다. 사과 1회와 감사 1회(또는 둘 중 한 종류 2회)를 가장 자연스러운 위치에 배치하되, 같은 표현을 두 번 쓰지 않는다.

[메일 형식]
제목 / 인사 / 청구 내역 확인 / 일정 문의 / 대안 요청 / 마무리 순서로 쓴다.
정확한 날짜가 어렵다면 대략적인 지급 예정 시기(예: 몇 월 초·중순)라도 알려 달라고 요청한다.

[예시]
(예시 1) 입력: 거래처 가온전자 재무팀 / 청구서 INV-2026-0307 / 청구일 2026-09-10 / 약정 지급일 2026-10-10 / 금액 2,200,000원 / 상태: 약정 지급일 지났고 미입금
출력:
제목: [한빛디자인] INV-2026-0307 대금 지급 일정 확인 요청
안녕하세요, 가온전자 재무팀 담당자님. 한빛디자인 [담당자명]입니다.
2026-09-10에 청구한 INV-2026-0307(2,200,000원) 건은 약정 지급일이 2026-10-10으로 안내되어 있으나, 저희 쪽에서는 아직 입금 내역이 확인되지 않아 문의드립니다.
진행 중인 사항이 있다면 지급 예정일을 공유해 주시기 바랍니다. 정확한 날짜가 어렵다면 대략적인 시기(몇 월 초·중순 등)만으로도 충분합니다.
바쁘신 중에 번거로운 요청을 드려 죄송합니다. 확인해 주시면 감사하겠습니다.
한빛디자인 [담당자명] 드림

(예시 2) 입력: 거래처 가온전자 재무팀 / 청구서 INV-2026-0388 / 약정 지급일 2026-10-31 / 금액 1,540,000원 / 상태: 2026-10-20에 1차 문의 메일 발송, 회신 없음
출력:
제목: [한빛디자인] INV-2026-0388 대금 지급 일정 재문의
안녕하세요, 가온전자 재무팀 담당자님. 한빛디자인 [담당자명]입니다.

현재 진행 상황이나 지급 예정 시기를 간단히 전해 주시면 됩니다. 확정이 어렵다면 대략적인 시기도 괜찮습니다.
거듭 연락드려 송구합니다. 협조에 감사드립니다.

(예시 3) 입력: 거래처 가온전자 재무팀 / 청구서 INV-2026-0451 / 청구일 2026-11-03 / 금액 4,400,000원 / 상황: 거래처가 "정확한 지급일은 확정하기 어렵다"고 회신
출력:
제목: [한빛디자인] INV-2026-0451 대략적인 지급 예정 시기 문의

추가 요청을 드리게 되어 송구합니다.
```

## 4. Few-shot 예시와 기법 적용

### 4-1. Few-shot 예시

예시 전문은 3-1의 시스템 프롬프트에 들어 있습니다. 4건이며 그중 예시 4가 모호한 입력에 되묻는 흐름입니다.

| 예시 | 시나리오 | 입력 요약 | 비고 |
|---|---|---|---|
| 예시 1 | 약정 지급일이 지났는데 미입금 | INV-2026-0307, 2,200,000원, 약정 지급일 2026-10-10 | |
| 예시 2 | 이전 문의에 답이 없어 두 번째로 문의 | INV-2026-0388, 1,540,000원, 1차 문의 2026-10-20 | |
| 예시 3 | 거래처가 정확한 날짜는 어렵다고 회신 | INV-2026-0451, 4,400,000원, 청구일 2026-11-03 | 대략 시기를 요청 |
| 예시 4 | 모호한 입력 | "대금 언제 주는지 메일 좀 써줘." | **되묻기 흐름**: 정보를 되묻고 받은 뒤 메일 작성 |

### 4-2. Zero-shot 시도 결과와 Few-shot 적용 결과 비교

같은 모델(gpt-6)에 **같은 입력**(새봄물류·누리상사 총무팀·INV-2026-0521)을 사용했습니다. Zero-shot은 거래 정보와 메일 작성 요청만 입력했고, Few-shot은 시스템 프롬프트 v1과 예시 4건을 먼저 제공한 뒤 같은 거래 정보를 입력했습니다.

| 구분 | Zero-shot | Few-shot |
|---|---|---|
| 응답 위치 | 사용자가 2026-11-25에 확인한 실제 응답 전문(아래 수록) | 실행 로그 T4 응답 전문 |
| 모델 | gpt-6 | gpt-6 |
| 실행 일시 | 2026-11-25 | 2026-11-24 (실행 로그 기준) |
| 적용 | 시스템 프롬프트 없음, 예시 없음. 거래 정보와 메일 작성 요청만 입력 | 시스템 프롬프트 v1을 대화 첫 메시지로 입력하고 Few-shot 예시 4건 제공 (방법 B) |

**Zero-shot 응답 전문 (사용자 확인 원문, 편집 없음)**

```
[새봄물류] INV-2026-0521 대금 지급 일정 확인 요청

안녕하세요, 누리상사 총무팀 담당자님.\
새봄물류 [담당자명]입니다.

**1. 청구 내역 확인**

물류 대행 용역과 관련하여 아래와 같이 청구 내역을 전달드린 바 있습니다.
- 청구서 번호: INV-2026-0521
- 청구일: 2026년 11월 2일
- 청구 금액: 3,850,000원
- 약정 지급일: 청구일로부터 30일 이내

**2. 지급 일정 문의**

현재 해당 청구 건의 입금 내역이 확인되지 않아, 지급 예정일을 문의드립니다.

내부 지급 일정이 정해져 있다면 예상 입금 날짜를 알려 주시기 바랍니다.

**3. 대안 일정 요청**

정확한 지급 날짜를 안내하기 어려우신 경우, 대략적인 지급 예정 시기라도 공유해 주시면 내부 자금 일정 관리에 참고하겠습니다.

**4. 마무리**

확인 후 회신해 주시면 감사하겠습니다.

평소 원활한 업무 협조에 고맙습니다.

새봄물류\
[담당자명] 드림
```

**Few-shot 적용 응답 전문 (실행 로그 T4, 편집 없음)**

```
안녕하세요, 누리상사 총무팀 담당자님. 새봄물류 [담당자명]입니다.

2026-11-02에 청구한 물류 대행 용역 INV-2026-0521(3,850,000원) 건과 관련하여 문의드립니다. 해당 건의 약정 지급 조건은 청구일로부터 30일 이내로 안내되어 있습니다.

내부 정산 일정을 확인하고자 해당 건의 지급 예정일을 알려 주시면 됩니다.

정확한 지급 날짜가 아직 확정되지 않았다면, 대략적인 지급 예정 시기(몇 월 초·중순·말 등)라도 공유해 주시기 바랍니다.

바쁘신 중에 확인을 부탁드려 죄송합니다. 회신해 주시면 감사하겠습니다.

새봄물류 [담당자명] 드림
```

**두 응답에서 확인한 사실 항목**

| 항목 | Zero-shot | Few-shot |
|---|---|---|
| 제목 | 제목에 회사명과 청구서 번호를 포함 | 별도 제목 없음 |
| 인사 | 거래처 부서와 보내는 회사 담당자 자리 표시 | 거래처 부서와 보내는 회사 담당자 자리 표시 |
| 청구 내역 | 번호, 청구일, 금액, 약정 지급 조건을 목록으로 제시 | 거래 내용, 번호, 청구일, 금액, 약정 지급 조건을 본문에 서술 |
| 지급 일정 문의 | 예상 입금 날짜를 직접 요청 | 지급 예정일을 요청 |
| 대안 일정 | 정확한 날짜가 어려우면 대략적인 시기를 요청 | 정확한 날짜가 미정이면 대략적인 시기를 요청하고 예시도 제시 |
| 사과·감사 표현 | 감사 계열 표현 2회(“감사합니다”, “고맙습니다”) | 사과 1회, 감사 1회 (합계 2회) |
| 마무리 | 회신 요청 뒤 업무 협조에 대한 감사 표현 | 확인 요청 및 회신에 대한 감사 표현 |

**비교 기록 (응답 원문 대조):** 이번에 확인한 Zero-shot과 Few-shot 응답은 **동일하지 않습니다.** Zero-shot은 제목과 번호가 붙은 소제목으로 청구 내역·일정 문의·대안 요청·마무리를 구분하고, 청구 정보를 목록으로 제시했습니다. Few-shot은 제목이나 소제목 없이 본문 문단으로 구성했으며, 거래 내용과 청구 정보를 한 문장에 담았습니다. 두 응답 모두 청구서 번호, 청구일, 금액, 약정 지급 조건을 입력과 일치하게 반영했고, 정확한 지급 날짜와 대략적인 시기를 요청했습니다. Zero-shot은 “예상 입금 날짜”를 직접 요청하고, Few-shot은 “지급 예정일”을 요청한 점에서 의미는 유사합니다.

**비교의 한계:**

- Zero-shot에는 시스템 프롬프트가 없고 Few-shot에는 페르소나·금지 규칙·표현 규칙과 예시가 포함된 v1을 사용했으므로, 관찰된 차이를 예시 제공만의 효과로 단정할 수 없음
- 각 조건을 한 번씩 실행한 결과이므로 재현성이나 일반적인 효과까지 판단할 수 없음
- 실행 일시가 서로 다름

### 4-3. 단계적 추론 유도 추가 여부

- **추가 여부:** 더하지 않음 (Zero-shot과 Few-shot만 사용)
- **이유:** 이번 과업은 거래처에 보낼 메일의 완성본을 만드는 것이므로, 별도의 단계별 추론을 유도하기보다 역할, 우선순위, 금지 사항, 메일 구성, Few-shot 예시로 필요한 작성 기준을 직접 제시하는 방식을 선택함. 실행 기록(run-log.md 작업 기록 6번)에도 단계적 추론 유도는 더하지 않기로 했다고 기록되어 있음.

### 5-2. 사실 정확성·환각 방지 및 후속 조치 제안 평가

기존 판정에서는 사실을 정확하게 답했는지와 답변 이후 확인 절차를 제안했는지를 하나의 Pass/Fail 기준으로 평가했습니다. 이를 두 항목으로 분리했습니다.

- **평가 A — 사실 정확성 및 환각 방지:** 확인된 정보는 정확하게 답하고, 전달받지 않은 정보는 임의로 만들어 내지 않으며, 모르는 정보는 모른다고 밝히는가?
- **평가 B — 후속 조치 제안:** 정보가 없거나 불확실한 경우, 사용자에게 필요한 정보를 요청하거나 확인 방법·다음 조치를 제안하는가?

두 항목은 독립적으로 판정합니다. 사실을 정확하게 답했더라도 후속 조치를 제안하지 않았다면 평가 A는 Pass, 평가 B는 Fail이 될 수 있습니다. 판정은 직접 했습니다.

| 번호 | 질문 (턴) | 정답 | 사실 정확성·환각 방지 | 후속 조치 제안 |
|---|---|---|---|---|
| Q1 | 지금까지 이야기한 청구서 번호가 뭐였지? (T9) | INV-2026-0521 | Pass | 해당 없음 |
| Q2 | 금액이 뭐였지? (T9) | 3,850,000원 | Pass | 해당 없음 |
| Q3 | 약정 지급일은 날짜로 언제야? (T11) | 2026-12-02 (청구일 11/2 + 30일) | Pass | 해당 없음 |

| Q5 | 우리 회사 이름이 뭐였지? (T15) | 새봄물류 | Pass | Fail |
| Q6 | 거래처가 알려 준 지급 가능 시기도 다시 말해 줘 (T15) | 12월 중순 이후 | Pass | Fail |

**재판정 설명 (사용자 판단):**

- **Q4 (T14):** 담당자 이름을 전달받지 못했다고 답했으며, 이름을 임의로 만들어 내지는 않았습니다. 사실 정확성·환각 방지 측면은 Pass입니다. 다만 추가 정보를 요청하거나 확인 방법을 제안하지 않아 후속 조치 제안은 Fail입니다.
- **Q5, Q6 (T16):** 회사명과 지급 가능 시기를 정확하게 회상했고 근거 정보와도 일치합니다. 사실 정확성·환각 방지 측면은 Pass입니다. 다만 답변 이후 확인이나 구체화를 위한 질문·제안이 없어 후속 조치 제안은 Fail입니다.
