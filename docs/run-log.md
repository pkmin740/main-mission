## 2. 작업 기록
- 과업 선정: 거래처 입금 시기 문의 이메일 대필(정산 도우미).
- 입력 항목과 출력 형식 정의: 거래처명, 담당자명, 세금계산서 발행일, 청구서 번호, 이전 문의 이력 등을 받아 정중한 입금 시기 문의 메일 작성.
- 모델 3종 비교 후 GPT-6 선정 (세부 결과는 model-comparison 문서 참조).
- 페르소나 기반 시스템 프롬프트 v1 작성 후, 입력 누락 확인 규칙을 v2에 추가하고 간결성 규칙을 v3에 추가함.
- 이번 본 테스트는 v3을 최종 설정으로 사용함.
- Few-shot 3개(최초 문의, 재문의, 담당자명 누락) 별도 테스트 완료. 최초 문의/재문의 예시에서 표현 중복이 관찰되어 간결성은 부분 통과. 담당자 누락 예시는 작성 전에 확인을 요청해 통과.
- 본 테스트 전 v3 및 Few-shot 예시 3개를 설정하고 AI가 예시 확인 완료라고 응답함.
- 본 테스트에서 동일 입력 반복, 이전 문의 조건 변경, 사실 확인 질문 5개, 담당자명 누락 상황을 검증함.

## 5. 로그 지점 표시 및 평가
- **동일 입력 반복:** 두 사용자 입력은 거래 정보와 요청 문구까지 동일함. AI 출력도 완전히 동일하여 반복 입력 일관성 통과.
- **조건 변경:** 이메일 1회 및 전화 2회 문의 이력을 정확하게 반영함.
- **검증 질문 1~4:** 발행일, 청구서 번호, 담당자, 이전 문의 이력을 정확하게 답하고 입력 정보를 근거로 제시함. 4개 모두 Pass.
- **검증 질문 5 (금액 및 기한):** 금액과 입금 기한이 제공되지 않았다고 정확히 밝혔고 추측하지 않았음. 다만 검증 기준 B(모르는 내용이라고 밝히면서 확인 방법도 제안)에 필요한 확인 절차/방법 제안이 없어, 엄격한 기준으로는 **Fail** 처리.
- **검증 결과:** 5개 질문 중 4개 Pass, 1개 Fail. (Q5는 사실을 꾸며낸 환각이 아니라, 검증 기준에서 확인 방법 제안이 빠진 경우임.)
- **담당자 누락:** 담당자명이 비어 있음을 지적하고 메일 작성 전에 확인 요청. 담당자 없이 작성할 수 있다는 선택권도 안내. 통과.
- **환각:** 관찰되지 않음.
- **맥락 손실:** 관찰되지 않음.
- **간결성:** 최초 문의 응답에서 '번거로우시겠지만'과 '업무 중 번거롭게 해드려 죄송하며'가 중복됨. 재문의 응답에서도 양해·배려 표현과 확인/회신 요청이 겹침. 부분 통과.
- **금지 표현/허위 정보:** 금지 표현 및 법적 조치 언급 없음. 입력에 없는 날짜·금액·번호·기한 생성도 관찰되지 않음.
