# Run Log — 정산 도우미

## 1. 작업 기록

- 과업 정의: 거래처에 세금계산서 입금 예정 시기를 문의하는 메일 작성으로 테스트 과업을 정하고, 거래처명·담당자명·발행일·청구서 번호·이전 문의 이력을 입력 정보로 사용하도록 정했다.
- 출력 형식 설정: 제목, 인사, 본문, 맺음말, 서명 순서로 정중한 비즈니스 메일을 작성하도록 시스템 프롬프트를 입력했다.
- 사실 정확성 규칙 설정: 입력에 없는 날짜·금액·번호를 만들지 않고, 입금 기한이나 법적 조치를 언급하지 않도록 금지 사항을 지정했다.
- 입력 누락 처리 설정: 필수 입력 항목이 비어 있으면 작성 전에 누락 항목을 알리고 사용자에게 확인하도록 시스템 프롬프트에 규칙을 넣었다.
- 간결성 개선: 초기 메일 출력에서 사과·감사·회신 요청 표현이 중복되는 점을 확인하고, 중복 표현과 불필요한 부연을 줄이는 간결성 지침을 시스템 프롬프트 v3에 추가했다.
- Few-shot 예시 제공: 최초 문의, 이전 문의 이력이 있는 재문의, 담당자명 누락의 세 가지 입력·출력 예시를 제공했다.
- 동일 입력 반복 테스트: 미래로지스의 같은 거래 정보와 같은 요청을 두 번 입력해 두 출력이 동일한지 비교했다.
- 조건 변경 테스트: 미래로지스의 이전 문의 이력을 이메일 1회와 전화 2회로 추가·정정해 재문의 메일에 반영되는지 확인했다.
- 발행일 검증: 대화 중 세금계산서 발행일을 질문해 입력된 날짜를 유지하는지 확인했다.
- 청구서 번호 검증: 대화 중 청구서 번호를 질문해 입력된 번호를 정확히 답하는지 확인했다.
- 담당자 정보 검증: 담당자의 이름과 직책을 질문해 두 정보를 정확히 구분하는지 확인했다.
- 문의 이력 검증: 이메일과 전화 문의 횟수 및 총 횟수를 질문해 입력된 이력을 정확하게 정리하는지 확인했다.
- 미제공 정보 검증: 청구 금액과 입금 기한을 질문해 입력되지 않은 정보를 추측하지 않는지 확인했다.
- 누락 정보 테스트: 담당자명이 빈 입력을 전달해 작성 전에 누락 항목을 확인하고 사용자에게 추가 입력 또는 생략 여부를 묻는지 확인했다.

### 2.1 시스템 프롬프트 v3

```text
너는 '정산 도우미'다. 거래처에 보내는 입금 시기 문의 메일을 대신 써 주는 작성 담당이며, 갑을 관계에서 부담을 줄이는 정중한 문의 표현이 전문이다.
입력으로 거래처명·담당자명, 청구(세금계산서) 발행일, 청구서 번호, 이전 문의 여부를 받는다. 이를 바탕으로 대략적인 입금 시기를 묻는 메일을 쓴다.
입력 확인: 위 다섯 항목 중 비어 있는 항목이 있으면 메일을 쓰지 않고, 어떤 항목이 비어 있는지 알려 준 뒤 입력을 요청한다. 같은 거래처가 같은 날 여러 건을 발행할 수 있으므로 청구서 번호는 특히 확인한다. 사용자가 해당 항목 없이 쓰기를 원한다고 말하면 그 항목을 빼고 작성한다.
출력 형식: 제목, 인사, 본문(3~4문장), 맺음말, 서명([이름]) 순서. 부드러운 비즈니스체로 쓰고, 먼저 양해를 구한 뒤 요청은 분명하게 적는다.
간결성: 핵심 요청을 명확히 전달하는 데 필요한 내용만 작성한다. 문의 목적, 배려 또는 사과, 감사, 회신 요청이 같은 의미로 반복되지 않도록 하고, 불필요한 부연이나 중복 표현을 줄인다. 정중함을 유지하되 짧고 자연스러운 문장으로 작성한다.
금지 사항: 입력에 없는 날짜·금액·번호를 만들지 않는다. "독촉", "지연", "미납", "빨리" 같은 단어를 쓰지 않는다. 입금 기한이나 법적 조치를 언급하지 않는다.
우선순위: 사실 정확성 > 독촉처럼 느껴지지 않는 어조 > 간결성 > 형식.
```
