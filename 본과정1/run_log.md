## 2. 작업 기록
- 과업 정의: 거래처 입금 시기 문의 메일 대필('정산 도우미')로 정하고 입력 6항목과 메일 출력 규격을 문장으로 적음[cite: 4, 6]
- 모델 세 종 비교: 같은 과업 프롬프트로 결과를 모으고 형식·정확도 등 비교 기준을 세워 GPT-6을 선정함[cite: 1]
- 프롬프트 v1 및 예시 작성: 페르소나 6요소를 담은 시스템 프롬프트 v1과 신규·재문의·번호 누락 되묻기 예시 3건을 작성함[cite: 4, 5]
- Zero-shot과 Few-shot 비교: 예시 유무에 따른 출력 형식 일관성과 번호 누락 시 되묻기 동작 차이를 대조함[cite: 8]
- 본 대화 및 검증 수행: GPT-6에서 입력 반복, 이전 문의 조건 변경, 환각 검증 질문 5건을 포함한 18턴 대화를 수행하고 모두 Pass 판정함[cite: 11, 15, 17]
- 프롬프트 v2 개선: 필수 항목(특히 청구서 번호) 누락 시 메일을 쓰지 않고 되묻는 '입력 확인' 규칙을 시스템 프롬프트에 추가함[cite: 20, 21]

## 4. 로그 지점 표시
- **동일 입력 반복 확인 (턴 4 vs 턴 6):** 입력 C를 두 번 동일하게 넣었을 때 본문 둘째 문장 끝 표현(`어떻게 되는지` → `언제쯤인지`) 한 곳만 달라졌으며, 핵심 값과 뜻·맥락에는 차이가 없어 실무 사용에 문제없음으로 판단함[cite: 14, 19, 20].
- **조건 변경 반영 확인 (턴 7 → 턴 8, 턴 16):** 턴 7에서 정정한 `지난주 이메일로 1회`가 턴 8 메일과 턴 16 답변에 모두 반영됨[cite: 14, 28, 29].
- **환각 발생 지점:** 없음 (검증 질문 5건 모두 Pass 판정)[cite: 17, 19, 20].
- **문맥 끊김 지점:** 없음 (정정 전 값으로 되돌아가거나 이전 조건을 놓친 곳 없음)[cite: 14, 19, 20].
- **금지 단어 및 표기 점검:** 금지 단어(`독촉`, `지연`, `미납`, `빨리`) 및 임의 날짜·금액·기한·법적 조치 언급 없음[cite: 19, 20]. 발행일 띄어쓰기(`2026년11월17일` → `2026년 11월 17일`)는 날짜 값이 같고 실무 사용에 지장이 없어 오류 지점으로 남기지 않음[cite: 14, 19, 20].
