# 1. 시스템 프롬프트 및 설계 (`system-design.md`)

## 1.1 설계 개요 및 Zero-shot vs Few-shot 비교
- **과업 목적:** 대금 정산 및 지급 기준 안내 메일 초안을 일관된 기준과 격식 있는 어조로 작성한다.
- **선정 모델:** Claude Sonnet 5.5
- **단계적 추론 유도:** 모델이 한 번에 답변을 쏟아내지 않도록 아래 순서로 판단하도록 프롬프트에 단계를 명시했다.
  1. 입력에서 확정된 지급 조건, 예외·특약 조건, 제외 요청 항목, 미정 항목을 분리해 파악한다.
  2. 지급 기산일이나 적용 시점 기준이 모호한지 점검한다.
  3. 기준일이 모호해 오안내 위험이 크면 메일 초안을 바로 쓰지 않고 확인 질문을 먼저 출력하며, 초안 작성 시 입력에 없는 세금계산서 발행 기한이나 공휴일·주말 순연 기준 등을 추측하지 않고 `[확인 필요 / 추후 안내 예정]`으로 표기한다.

### Zero-shot 적용 시 vs Few-shot 적용 후 차이
- **Zero-shot 테스트 결과 (예시 없이 규칙·추론 절차만 제공):**
  - 미정 항목(세금계산서 발행 기한, 공휴일·주말 순연 기준 등)을 추측하지 않고 `[확인 필요 / 추후 안내 예정]`으로 표기하는 규칙과, 기준일("원도에서 대금 주는 대로")이 모호할 때 메일 초안 대신 확인 질문을 먼저 던지는 판단 흐름은 정상 작동했다.
  - 다만, 예시가 없다 보니 본문 지급 구조에서 `원도 → 하도` 대신 `원도급사 → 하도급사`로 용어가 변형되었고, 메일 초안 앞에 모델의 내부 처리 설명("초안 작성 시 처리 내용은 다음과 같습니다...")이나 이전 대화 맥락("에이테크, 시소페인트 메일도...")이 함께 출력되어 곧바로 복붙해 쓰기에는 출력 포맷이 일정하지 않았다.
- **Few-shot 적용 후 개선된 점:**
  - 출력 예시 3종을 함께 제공하자 메일 본문 앞뒤의 불필요한 부연 설명이 줄고, 제목–인사–지급 구조–정산·지급 기준–맺음말로 이어지는 표준 메일 양식과 용어 통일성이 안정적으로 고정되었다.

## 1.2 시스템 프롬프트

```text
[페르소나]
당신은 기업의 대금 정산 및 지급 기준을 거래처에 정확하고 정중하게 안내하는 전담 '정산 안내 매니저'입니다.
현장이나 실무에서 오가는 정산 조건을 꼼꼼히 파악해, 오해나 누락 없이 안내 메일을 정리하는 역할을 맡습니다.

[단계적 추론 절차]
답변을 만들기 전에 반드시 다음 순서로 판단하세요.
1단계: 입력에서 확정된 지급 조건, 예외·특약 조건, 제외 요청 항목, 미정 항목을 구분합니다.
2단계: 지급 기산일이나 지급 시점 기준이 모호한 항목이 있는지 확인합니다.
3단계: 기준일이 모호해 오안내 위험이 크면 메일 초안을 바로 작성하지 말고 확인 질문을 먼저 제시합니다. 초안을 작성할 때는 입력에 없는 세금계산서 발행 기한이나 공휴일·주말 순연 기준 등을 추측하지 말고 '[확인 필요 / 추후 안내 예정]'으로 표기합니다.

[핵심 규칙]
1. 호칭 및 용어 통일:
   - 수신 거래처는 본문에서 반드시 '귀사'로 호칭합니다.
   - 기본 대금 지급 흐름은 '원도 → 하도 → 당사 → 귀사'로 표기합니다(단, 사용자가 특정 항목 제외를 요청한 경우 해당 항목을 뺍니다).
2. 정보 누락 및 미정 항목 처리 (추측 금지):
   - 입력에 명시되지 않은 정보(세금계산서 발행 기한, 공휴일·주말 순연 기준 등)는 절대 임의로 추측하거나 기본값을 만들어 적지 않습니다.
   - 확정되지 않은 항목은 반드시 '[확인 필요 / 추후 안내 예정]'으로 표기합니다.
3. 조건 구분 및 구조화:
   - 기본 지급 기준과 거래처별 예외·특약 조건(선지급금, 기산점 변경 등)이 함께 있는 경우, 혼동되지 않도록 항목을 분리하여 안내합니다.
   - 사용자가 지급 구조 설명 생략 등 특정 항목 제외를 명시적으로 요청한 경우에만 해당 섹션을 제외합니다.
4. 모호한 입력에 대한 사전 확인:
   - 지급 기산일이나 적용 시점이 모호하게 입력된 경우(예: "대금 주는 대로", 기준 시점 불명확 등), 메일 초안을 바로 작성하지 말고 먼저 명확화를 위한 확인 질문을 합니다.
5. 어조 및 출력 형식:
   - 정중하고 간결한 비즈니스 한국어 격식체(~합니다, ~바랍니다)를 사용합니다.
   - 메일 제목, 수신인 인사, 지급 구조, 정산·지급 기준, 문의 및 맺음말 순으로 일관된 구조를 유지합니다.
```

## 1.3 유저 프롬프트 (작성 요청 방식)

유저 프롬프트에서는 대상 거래처명, 포함하거나 제외할 항목, 선지급·잔금·예외 지급 기준, 미정 여부 등을 자연어로 전달한다.

- **예시 문장:**
  > "거래처 A 정산 안내 메일 써줘. 선지급 50%는 계약체결일 기준이고 산정 기준은 미정이야. 잔금 50%는 원도 지급 완료일로부터 1개월 뒤 지급이야. 세금계산서 발행 기한이랑 공휴일 순연 기준은 미정으로 넣어줘."

---

## 1.4 그대로 복사해 쓰는 입력 템플릿

실무 테스트나 메일 초안 요청 시 아래 템플릿을 복사해 빈칸만 채워서 사용한다.

```text
[대상 거래처]:
[지급 구조 포함 여부]: (포함 / 제외 — 예: 지급 구조 설명 및 원도 지급 기준 제외)
[선지급 / 잔금 / 지급 기준]:
[예외 또는 특약 조건]:
[세금계산서 발행 기한]: (확정 내용 또는 미정)
[공휴일·주말 순연 기준]: (확정 내용 또는 미정)
[기타 참고 사항]:
```

## 1.5 Few-shot 예시 (3종)

### [예시 1] 기본 구조 + 분할 지급 및 미정 항목 표준 표기
- **유저 입력:**
  > 거래처 A 정산 안내 메일 써줘. 선지급 50%는 계약체결일 기준 지급이고 산정 기준은 미정이야. 잔금 50%는 원도 지급 완료일로부터 1개월 뒤에 지급해. 세금계산서 발행 기한이랑 공휴일 순연 기준은 아직 안 정해졌어.
- **모델 출력:**
  > **제목:** [당사] 대금 정산 및 지급 기준 안내의 건
  >
  > 거래처 A 담당자님께,
  >
  > 안녕하세요. 항상 협조해 주셔서 감사드립니다.
  > 귀사에 적용되는 정산 및 대금 지급 기준을 아래와 같이 안내드립니다.
  >
  > **■ 지급 구조**
  > 원도 → 하도 → 당사 → 귀사
  >
  > **■ 정산·지급 기준**
  > 1. **선지급금 (50%):** 계약체결일 기준으로 지급합니다.
  >    - 산정 기준: [확인 필요 / 추후 안내 예정]
  > 2. **잔금 (50%):** 원도 지급 완료일로부터 1개월 뒤에 지급합니다.
  > 3. **세금계산서 발행 기한:** [확인 필요 / 추후 안내 예정]
  > 4. **공휴일·주말 순연 기준:** [확인 필요 / 추후 안내 예정]

  > 위 기준과 관련하여 문의사항이 있으시면 언제든지 연락해 주시기 바랍니다.
  > 확정되지 않은 항목은 정리되는 대로 별도로 안내드리겠습니다.
  > 앞으로도 원활한 협력을 부탁드립니다.
  >
  > 감사합니다.
  > [회사명] [담당자 성명] 드림

## 1.6 프롬프트 개선 히스토리 (설계 반영 사항)
- **1차 설계 (초기):** 역할과 기본 메일 형식만 부여 → 미정 항목을 임의로 가정하거나, 모호한 조건에도 그대로 메일을 생성하는 문제 발생.
- **2차 설계 (개선):** `[확인 필요 / 추후 안내 예정]` 고정 문구 규칙 및 '모호한 입력 시 선(先) 질문 후(後) 작성' 규칙 추가 → 누락 항목 추측이 줄고 불명확한 기산점을 사전에 걸러낼 수 있게 됨.
- **3차 설계 (최종):** 단계적 추론 절차, 입력 템플릿, Few-shot 예시 3종(분할·미정, 예외 분리, 모호성 되묻기)을 결합해 출력 포맷과 용어 일관성을 확보함.

## 2.2 주요 테스트 로그

### [Zero-shot 비교 테스트] 거래처 A·두산테크 — 예시(Few-shot) 미제공 상태 검증
- **테스트 내용:** 시스템 프롬프트의 페르소나, 단계적 추론 절차, 핵심 규칙만 제공하고 Few-shot 예시를 제외한 상태로 거래처 A(선지급 50% 계약체결일 기준, 잔금 50% 원도 지급 완료일 + 1개월, 미정 항목 포함)와 두산테크(모호한 잔금 기산일 포함)를 테스트함.
- **검증 결과:**
  - 거래처 A 건에서는 미정 항목(선지급 산정 기준, 세금계산서 발행 기한, 공휴일·주말 순연 기준)을 추측 없이 `[확인 필요 / 추후 안내 예정]`으로 표기했으나, 메일 본문 위에 모델의 처리 설명 문구가 길게 붙고 지급 구조에 '원도급사', '하도급사' 용어가 사용됨.
  - 두산테크 건에서는 "원도에서 대금 주는 대로"의 기준이 모호하다고 판단해 메일 초안 대신 A/B 선택지를 포함한 확인 질문을 먼저 출력했으나, 마지막 줄에 이전 대화 맥락(에이테크, 시소페인트 언급)이 덧붙음.
  - **시사점:** 핵심 규칙과 되묻기 판단은 제로샷에서도 작동하지만, 출력 포맷과 용어를 일정하게 고정하기 위해 Few-shot 예시 결합이 필요함을 확인함.

### [Turn 1] 거래처 A 안내 메일 — 분할 지급(선지급·잔금) 및 미정 항목 처리 검증
- **테스트 내용:** 선지급 50%(계약체결일 기준, 산정 기준 미정)과 잔금 50%(원도 지급 완료일로부터 1개월 뒤) 조건, 그리고 세금계산서 발행 기한 및 공휴일·휴일 순연 기준 미정 상태를 입력하여 초안 생성을 검증함.
- **검증 결과:**
  - 선지급 50%와 잔금 50% 기준을 분리해 안내함.
  - 입력되지 않은 세금계산서 발행 기한과 공휴일·휴일 순연 기준을 추측하지 않고 `[확인 필요 / 추후 안내 예정]`으로 표기함.

### [Turn 2] 거래처 B 안내 메일 — 기본 지급 구조 및 예외 지급 기준 분리 검증
- **테스트 내용:** 기본 지급 구조 안내와 함께 예외적으로 세금계산서 발행 완료일로부터 2주 뒤 지급하는 조건, 미정 항목(세금계산서 발행 기한, 공휴일·휴일 순연 기준)을 입력하여 검증함.
- **검증 결과:**
  - 기본 지급 구조와 예외 적용 기준(세금계산서 발행 완료일로부터 2주 뒤 지급)을 구분하여 안내함.
  - 미정 항목은 `[확인 필요 / 추후 안내 예정]`으로 일관되게 표기함.

### [Turn 3] 두산테크·시스엔 동시 요청 — 모호한 기준일 되묻기 및 이전 맥락("전처럼") 반영 검증
- **테스트 내용:** 한 요청에 두산테크(선지급금 50% 부가세 포함, 잔금은 공사 종료 후 원도 대금 수령 기준 영업일 7일 이내)와 시스엔("전처럼" 원도→하도 2주 후 1개월 말일 지급, 세금계산서 말일 발행)을 함께 입력함.
- **검증 결과:**
  - 두산테크 건은 "원도에서 대금 주는 대로"의 기준이 모호하다고 판단해 메일을 바로 쓰지 않고 잔금 기산점, 선지급 기준 금액/시기, 세금계산서 발행 기한을 확인 요청함.
  - 시스엔 건은 이전 대화("전처럼") 맥락을 반영해 메일 초안을 작성하고 미정인 공휴일·주말 순연 기준을 `[확인 필요 / 추후 안내 예정]`으로 표기함.
  - 한 응답 안에서 두산테크는 확인 요청, 시스엔은 메일 초안으로 처리 방식이 나뉘었고, 지급 구조 표기에서 '원도' 대신 '원도급사', '하도급사'가 사용됨.

### [Turn 4] 두인씨스트 안내 메일 — 특정 섹션 제외 및 확정 조건 반영 검증
- **테스트 내용:** 지급 구조 설명과 원도 지급 기준을 제외하고, 당사가 원도 지급 완료일로부터 1개월 뒤 지급하는 내용과 세금계산서 "매월 점검 끝나고 말일" 발행을 지정해 요청함.
- **검증 결과:**
  - 요청대로 지급 구조 설명과 원도 지급 기준을 제외하고, 당사 지급 기준(원도 지급 완료일로부터 1개월 뒤, 예시 포함)과 세금계산서 말일 발행을 본문에 반영함.
  - 미정인 공휴일·주말 순연 기준은 `[확인 필요 / 추후 안내 예정]`으로 표기함.
  - 본문 하단에 '점검'의 의미와 확인 주체를 묻는 확인 문구가 추가로 생성되었고 '원도급사' 용어가 쓰임.

### [Turn 5] 에이테크·시소페인트·(주)부산행연 복합 조건 — 다중 예외 및 다중 맥락 참조 검증
- **테스트 내용:** 선지급 40%(착공일 기준)와 잔금(원도 지급 완료일 + 1개월)이 섞인 에이테크, 과거 거래처(엔소프트, 시스엔, 두인씨스트)별 기준 차이와 공휴일 순연("말일 이전 영업일 지급")·원도 지급 지연 순연 조건이 얽힌 시소페인트, 세금계산서 발행 완료일로부터 2주 뒤 지급 조건의 (주)부산행연을 한 번에 요청함.
- **검증 결과:**
  - 에이테크는 선지급 부가세 포함 여부, 착공일 기준 시점, 잔금 지급일의 당일/말일 여부를 짚어 확인 요청함.
  - 시소페인트는 이전 거래처별 기준 차이를 정리해 "전처럼"의 기준을 되묻고, 공휴일 순연 기준("말일 이전 영업일 지급")이 엔소프트와 다르다는 점과 원도 지급 지연 순연 반영 여부를 정리함.
  - (주)부산행연은 요청에 맞춰 지급 구조와 원도 지급 기준을 생략하고, 세금계산서 발행 완료일로부터 2주(달력일 14일) 뒤 지급 기준과 미정 항목 `[확인 필요 / 추후 안내 예정]`을 반영한 메일 초안을 작성함.

## 2.3 종합 검증 요약
- **강점:** 미정 항목 `[확인 필요 / 추후 안내 예정]` 표기, 조건 분리, 모호한 기준일 사전 질문, 이전 대화 맥락 참조 및 복합 조건 정리 능력이 안정적으로 작동함.
- **검수 필요 사항:** 다중 거래처 요청 시 거래처별 질문/작성 방식 혼재, '원도' 용어의 '원도급사' 변형, 확정 조건 입력 시에도 추가 확인 문구가 붙는 경우가 있어 발송 전 최종 검수가 필요함.

- **평가 기준:**

  3. **복합 조건 구조화:** 선지급·잔금 분할, 예외 기준 분리, 다중 거래처 요청 정리 능력
  4. **실무 문체 적합성:** 비즈니스 메일에 적합한 격식 있고 자연스러운 한국어 어조 유지 여부

## 3.3 최종 선정 모델: Claude Sonnet 5.5

### 선정 사유
1. **복합 조건 및 맥락 추적 능력:** 분할 지급(선지급·잔금), 예외 기산점, 미정 항목 처리, 이전 거래처 기준("전처럼") 참조 등 여러 조건이 얽힌 요청에서도 기준을 정리해 반영하는 능력이 안정적이었다.
2. **모호한 입력에 대한 선제적 확인:** 지급 기산일이나 적용 시점이 불분명할 때 추측해서 메일을 완성하기보다 확인 질문을 먼저 던져 잘못된 안내 발송 위험을 줄였다.
3. **실무 메일 형식의 완성도:** 안내 메일의 구조와 정중한 격식체를 일관되게 유지해 초안 검토 및 수정 시간을 단축할 수 있다.

### 유의점 (선정 후 검수 포인트)
- 한 번의 요청에 여러 거래처를 함께 넣을 경우 거래처별로 확인 요청과 메일 초안 작성이 섞여 나올 수 있다.
- '원도' 대신 '원도급사'로 표기되거나 확정 조건 입력 시에도 추가 확인 문구가 덧붙는 경우가 있으므로, 최종 발송 전 용어와 불필요한 문구 포함 여부를 점검해야 한다.
